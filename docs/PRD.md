## 1. 产品概述

| 项目 | 内容 |
|------|------|
| **产品名称** | 心愿拾光 |
| **一句话描述** | 一款面向情侣的微信小程序，让两人共建愿望池、随机抽取活动、打卡记录美好瞬间，最终生成专属回忆录。 |
| **目标用户** | 18-35 岁情侣/伴侣群体，日常缺乏活动灵感、希望增加共同体验和仪式感 |
| **核心价值主张** | 「不知道做什么？抽一个。」——把情侣间的模糊期待变成可执行的行动，把行动变成可回味的记忆。 |
| **平台** | 微信小程序 |
| **后端方案** | 微信云开发（CloudBase） |
| **技术栈** | 小程序原生框架 + WeUI 组件库 + 云函数 + 云数据库 + 云存储 |

### 1.1 产品目标

| # | 目标 | 衡量指标 |
|---|------|----------|
| G1 | **降低决策成本**：解决情侣「今天做什么」的选择困难，30 秒内完成随机抽取决策 | 平均抽取决策时长 < 30s；周活跃抽取次数 ≥ 2 次/对 |
| G2 | **沉淀共同回忆**：通过打卡 + 媒体上传，将零散的活动记录结构化为可回顾的回忆录 | 打卡率（抽取后完成打卡）≥ 60%；回忆录生成覆盖率 ≥ 80% |
| G3 | **增强情感连接**：通过愿望共建、共同打卡等互动机制，提升情侣间的参与感和仪式感 | 愿望池共建率（双方均有录入）≥ 70%；次日留存率 ≥ 40% |

## 2. 用户故事

| # | 角色 | 故事 |
|---|------|------|
| US1 | 作为一名情侣用户 | 我希望与伴侣绑定贴贴关系，**以便**我们共享同一个愿望池，双方都能看到和操作 |
| US2 | 作为一名情侣用户 | 我希望随时录入想做的事情（吃喝玩乐均可），**以便**把灵感积累起来不再遗忘 |
| US3 | 作为一名情侣用户 | 我希望在无聊时从愿望池中随机抽取一个活动，**以便**快速决定接下来做什么，增加惊喜感 |
| US4 | 作为一名情侣用户 | 我希望抽完后可以选择放回或标记完成，**以便**灵活管理愿望的去留 |
| US5 | 作为一名情侣用户 | 我希望完成活动后能打卡并上传照片/视频，**以便**记录我们的共同经历 |
| US6 | 作为一名情侣用户 | 我希望基于打卡记录自动生成回忆录，**以便**随时翻阅我们的美好时光 |

## 3. 需求池

### P0 · 必须有（MVP 核心闭环）

| ID | 需求 | 描述 | 验收标准 |
|----|------|------|----------|
| P0-1 | 情侣贴贴绑定 | 一方发起邀请生成贴贴码/小程序码，另一方扫码或输入码完成绑定 | 绑定后双方共享同一愿望池；支持解绑 |
| P0-2 | 愿望池 CRUD | 双方均可创建、查看、编辑、删除愿望条目 | 双方数据实时同步；支持文字描述 |
| P0-3 | 随机抽取 | 从未完成愿望池中随机抽取一条，带动画效果 | 抽取结果可操作：放回 / 标记进行中 |
| P0-4 | 抽取后处理 | 抽取后提供「放回池中」和「开始去做」两个选项 | 选择「开始去做」后愿望状态变为「进行中」 |
| P0-5 | 打卡记录 | 活动完成后进行打卡，记录完成时间 | 打卡后愿望状态变为「已完成」；记录打卡人 |
| P0-6 | 照片上传 | 打卡时支持上传照片（1-9 张） | 照片存储到云存储；支持预览和删除 |

### P1 · 应该有（体验增强）

| ID | 需求 | 描述 | 验收标准 |
|----|------|------|----------|
| P1-1 | 视频上传 | 打卡时支持上传短视频（≤ 30s / ≤ 50MB） | 视频存储到云存储；支持播放预览 |
| P1-2 | 回忆录基础版 | 按时间线展示所有已完成打卡记录，含照片/文字 | 支持按月份浏览；自动按时间倒序排列 |
| P1-3 | 愿望分类标签 | 录入愿望时可选择分类标签（美食/旅行/运动/电影/居家/其他） | 支持按标签筛选愿望池 |
| P1-4 | 打卡文字备注 | 打卡时支持填写文字感受/笔记 | 文字长度 ≤ 500 字 |
| P1-5 | 愿望状态管理 | 愿望支持「待抽取 / 进行中 / 已完成」三态流转 | 状态变更双方同步可见 |

### P2 · 可以有（锦上添花）

| ID | 需求 | 描述 | 验收标准 |
|----|------|------|----------|
| P2-1 | 回忆录高级版 | 支持图文排版、模板选择、生成精美长图 | 提供至少 3 套排版模板；支持导出为图片保存 |
| P2-2 | 愿望完成统计 | 统计已完成了多少愿望、打卡次数、最常做的分类 | 数据可视化展示（进度条/饼图） |
| P2-3 | 分享功能 | 将回忆录或打卡记录分享到微信好友/朋友圈 | 分享卡片含小程序跳转链接 |
| P2-4 | 愿望收藏 | 对特别想做的愿望标记「置顶/收藏」 | 收藏项在抽取时有更高权重 |
| P2-5 | 纪念日提醒 | 设置情侣纪念日，到点推送提醒 | 支持多个纪念日；微信订阅消息推送 |

## 5. 数据模型概要

### 5.1 核心实体关系

```
User (用户)
 │
 ├── 1:1 ── Couple (情侣贴贴关系)
 │           │
 │           └── 1:N ── Wish (愿望)
 │                        │
 │                        └── 1:1 ── CheckIn (打卡记录)
 │                                      │
 │                                      └── 1:N ── Media (媒体文件)
 │
 └── 1:N ── Media (上传的媒体文件)
```

### 5.2 实体字段概要

#### User（用户）

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | String | 用户唯一标识 |
| `openid` | String | 微信 openid |
| `nickName` | String | 微信昵称 |
| `avatarUrl` | String | 头像 URL |
| `coupleId` | String | 关联的 Couple ID（未贴贴为空） |
| `createdAt` | Date | 注册时间 |

#### Couple（情侣贴贴）

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | String | 贴贴关系唯一标识 |
| `pairCode` | String | 6 位贴贴码（绑定后可清除） |
| `userA` | String | 用户 A 的 openid |
| `userB` | String | 用户 B 的 openid |
| `status` | String | `pending` / `active` / `unbound` |
| `anniversary` | Date | 贴贴纪念日（绑定时间） |
| `createdAt` | Date | 创建时间 |

#### Wish（愿望）

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | String | 愿望唯一标识 |
| `coupleId` | String | 所属情侣关系 ID |
| `title` | String | 愿望内容（必填） |
| `description` | String | 详细描述（选填） |
| `category` | String | 分类标签：`food` / `travel` / `sport` / `movie` / `home` / `other` |
| `status` | String | `pending`（待抽取）/ `ongoing`（进行中）/ `completed`（已完成） |
| `createdBy` | String | 创建人 openid |
| `drawnAt` | Date | 最近一次抽取时间 |
| `completedAt` | Date | 完成时间 |
| `isFavorite` | Boolean | 是否收藏/置顶（P2） |
| `createdAt` | Date | 创建时间 |

#### CheckIn（打卡记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | String | 打卡记录唯一标识 |

## 6. 待确认问题

| # | 问题 | 影响范围 | 建议 |
|---|------|----------|------|
| Q1 | 愿望池是否需要**隐私分级**（仅自己可见 vs 双方可见）？ | 数据模型、愿望录入 UI | 建议 MVP 阶段默认双方可见，后续可加隐私选项 |
| Q2 | 随机抽取是否需要**按分类/标签过滤**后再抽取？ | 抽取页交互 | 建议 P1 加入分类筛选后再抽取 |
| Q3 | 打卡是否需要**双方都确认**才算完成，还是任一方打卡即可？ | 打卡流程、状态流转 | 建议任一方打卡即可，降低摩擦 |
| Q4 | 视频上传是否需要**时长/大小限制**？云存储成本如何控制？ | 打卡页、云存储成本 | 建议 ≤ 30s / ≤ 50MB，超出提示压缩 |
| Q5 | 回忆录是否需要**导出为视频/图片**保存到本地？ | 回忆录功能、技术方案 | P2 阶段支持导出长图，视频导出成本较高暂不考虑 |
| Q6 | 是否需要**多情侣关系**切换（历史贴贴记录）？ | 数据模型、个人页 | 建议 MVP 仅支持单一活跃贴贴，解绑后可重新贴贴 |
| Q7 | 是否需要**消息通知**（如对方录入了新愿望、完成打卡提醒）？ | 云函数、订阅消息 | 建议 P1 接入微信订阅消息推送 |
| Q8 | 小程序是否需要**运营内容**（如推荐愿望模板、节日活动）？ | 内容管理、运营成本 | MVP 不做，P2 根据用户量考虑 |
